# AutoOps AI — Multi-Agent Workflow Automation System

Converts unstructured meeting transcripts into structured, trackable action items —
with automated assignment, due-date tracking, and escalation for anything that falls through the cracks.

## What it does

Feed it a raw meeting transcript. It runs the transcript through a 7-stage agent
pipeline and gives you back clean, owned, dated, trackable tasks instead of a wall of text.

```
ingest -> extract -> validate -> (retry) -> assign -> monitor -> escalate
```

## Architecture

| Agent | Responsibility |
|---|---|
| `IngestAgent` | Cleans raw transcript text, strips filler words, chunks long transcripts |
| `ExtractAgent` | Calls an LLM with a structured-output prompt to pull candidate action items |
| `ValidateAgent` | Filters extractions by confidence score |
| `RetryAgent` | Re-attempts extraction on low-confidence items (up to 3x) before giving up |
| `AssignAgent` | Matches each item to an owner, with round-robin fallback |
| `MonitorAgent` | Sets due dates based on priority, initializes tracking state |
| `EscalateAgent` | Flags unowned, overdue, or high-priority items for human review |

## Tech stack

- **Backend:** Python, FastAPI
- **LLM:** Anthropic Claude API (with a heuristic offline fallback for demos)
- **Storage:** in-memory for the demo build — swap `TASKS_DB`/`RUNS_DB` for Postgres/Redis in production

## How to run

```bash
git clone https://github.com/hemanthkumargt/AutoOps.git
cd AutoOps
pip install -r requirements.txt

export ANTHROPIC_API_KEY=your_key_here   # optional — falls back to heuristic extraction without it

uvicorn main:app --reload
```

API docs available at `http://localhost:8000/docs` (auto-generated by FastAPI).

## Example request

```bash
curl -X POST http://localhost:8000/pipeline/run \
  -H "Content-Type: application/json" \
  -d '{
    "transcript": "John: I will send the budget report by Friday. Sarah, can you follow up with the vendor?",
    "meeting_title": "Q3 Budget Sync",
    "participants": ["John", "Sarah"]
  }'
```

## Why it's built this way

Real meeting transcripts are messy — filler words, ambiguous ownership, no explicit
deadlines half the time. Splitting the pipeline into focused single-responsibility
agents (rather than one giant prompt) made each stage independently testable and
let me add a retry loop specifically for the extraction step, which is where most
of the failure cases actually showed up.
